1. First: save the BitLocker recovery key

Do this today

Without the 48-digit recovery key, a locked Windows drive cannot be opened, not even by Microsoft. Keep it outside this laptop: printed, on your phone, or in your Microsoft account.

  • Microsoft account: on any device open aka.ms/myrecoverykey, sign in with the account used on this Windows.
  • In Windows (Command Prompt as administrator): shows the key as "Numerical Password".
manage-bde -protectors -get C:
  • Or: Control Panel → System and Security → BitLocker Drive Encryption → Back up your recovery key (on Windows Home: Settings → Privacy & security → Device encryption).
  • The blue recovery screen shows a Key ID. The saved key whose ID starts the same way is the right one.

3. Problems and what to do

Picking Windows takes an extra restart normal
What you see

After choosing the Windows icon the background stays for a few seconds, the laptop restarts (HP logo), then Windows starts.

Why

BitLocker only unlocks when Windows is started by the laptop's firmware, the same way as without Ubuntu. GRUB therefore does not start Windows itself. It starts a tiny helper that asks the firmware to start Windows Boot Manager once (BootNext) and restarts. Only the firmware can start Windows the way BitLocker expects, so the restart cannot be removed without bringing back the key prompt.

What to do

Nothing. The request is used once; the next start shows the menu again.

BitLocker asks for the recovery key blue screen
What you see

A blue "BitLocker recovery" screen asking for a 48-digit key.

Why

The TPM chip only releases the key when the start-up looks exactly like when BitLocker was set up. Usual causes:

  • a BIOS/UEFI update (also offered by Ubuntu Software / fwupd, HP Support Assistant, Windows Update);
  • changes in the BIOS setup: Secure Boot on/off, TPM cleared or turned off, boot mode;
  • Windows started from GRUB by a "chainload" entry (only if os-prober was switched on again, or --windows-boot chainload). The Windows icon and F9 never do this.
What to do
  1. Type the recovery key (see section 1). Windows starts normally; nothing is lost.
  2. Restart once more. If Windows starts without asking, you are done.
  3. If it asks every time: in Ubuntu run the health check. It shows whether GRUB has a chainload entry or the Windows icon is in chainload mode.
cd ~/Desktop/grub-icon-menu
sudo ./doctor.sh
  1. After a deliberate change (BIOS update, Secure Boot change), make BitLocker accept the new state: in Windows, Control Panel → BitLocker → Suspend protection, restart, and it resumes by itself (or click Resume protection). In an administrator Command Prompt this is:
manage-bde -protectors -disable C: -RebootCount 1
The Windows icon shows a message instead of restarting nothing was changed

The helper only writes BootNext when everything is as expected. Otherwise it writes nothing, explains the problem in large text, and waits: Enter restarts into the menu, after 60 seconds the laptop turns off (so it can never loop). Windows was not started, so BitLocker was not involved. To get into Windows right now use Esc F9 → Windows Boot Manager.

Before a BIOS / firmware update avoid the key prompt
Why

A BIOS update changes what the TPM measures, so the next Windows start asks for the recovery key. That happens with or without Ubuntu.

What to do
  1. Have the recovery key ready (section 1).
  2. Prefer updating the BIOS from Windows (HP Support Assistant, Windows Update): they normally suspend BitLocker themselves.
  3. If you update from Ubuntu (Software app / fwupdmgr), first suspend BitLocker in Windows: Control Panel → BitLocker → Suspend protection, or in an administrator Command Prompt:
manage-bde -protectors -disable C: -RebootCount 2
  1. Then do the update, then start Windows with the Windows icon. BitLocker turns itself back on.

./doctor.sh warns when Ubuntu offers a BIOS/UEFI update.

The laptop starts Windows directly, no menu boot order
Why

Windows updates sometimes put Windows Boot Manager first in the firmware boot order.

What to do
  1. Power on, press Esc F9, choose Ubuntu.
  2. In Ubuntu, the health check prints the exact command that puts Ubuntu first again (it only reorders; nothing is deleted):
sudo ./doctor.sh
# for example:  sudo efibootmgr -o 0000,0001,0002,9999

Or in BIOS setup (Esc F10) → Boot options → move Ubuntu to the top.

No menu, black screen, or a grub> prompt GRUB problem
  1. If the icon menu looks wrong: press Esc for the full menu and choose Ubuntu.
  2. If GRUB does not start: power on, Esc F9 → Ubuntu or Windows Boot Manager. These firmware entries are never changed by grub-icon-menu.
  3. Once Ubuntu runs, switch the icon menu off (the plain menu keeps the safe Windows entry), or remove it:
sudo ./update.sh --plain        # plain text menu, Windows entry kept
sudo ./uninstall.sh             # or remove grub-icon-menu completely
  1. Every install/update made a backup; each one restores itself:
ls ~/grub-icon-menu-backup/
sudo ~/grub-icon-menu-backup/<snapshot>/restore.sh ~/grub-icon-menu-backup/<snapshot>

If Ubuntu does not start at all: repair from a live USB.

You installed another system (Kali, Linux Mint, Arch, ...) add its icon
What happens

The installer of the new system usually installs its own boot loader and puts it first in the firmware boot order. The next start then shows its menu, not the icons. Its menu may also offer "Windows Boot Manager": that entry starts Windows from GRUB and asks for the BitLocker recovery key. Don't use it.

What to do
  1. Start Ubuntu: power on, Esc F9 → Ubuntu (or pick Ubuntu in the new system's menu).
  2. Put Ubuntu first again. The health check prints the exact command:
cd ~/Desktop/grub-icon-menu
sudo ./doctor.sh                # e.g. sudo efibootmgr -o 0000,0001,0003,0002
  1. Add its icon:
sudo ./update.sh                # Kali, Fedora, Arch, Debian, ... (own boot entry)
sudo ./update.sh --os-prober    # Linux Mint, Zorin, elementary (share Ubuntu's)

Systems with their own boot entry are started by the firmware, like Windows. Up to 6 icons fit; more systems stay in the ESC menu. The 37 known systems are listed in icons/README.md.

Linux Mint, Zorin, elementary use the same boot folder as Ubuntu (\EFI\ubuntu). Installing one of them can replace Ubuntu's boot loader. If the icons do not come back after update.sh, reinstall Ubuntu's: sudo grub-install followed by sudo update-grub.

Background or icons look wrong looks only
  • Icons hard to see on the picture: force a colour or the shadow: sudo ./update.sh --icon-color white --shadow on (or black).
  • Picture looks soft: it is smaller than the screen and was enlarged. Use one at least 1920×1080.
  • Picture cut off at the sides: it is scaled to fill the screen; a 16:9 picture fits exactly.
  • Busy picture: choose one with a calm middle (where the icons are).
  • Back to the white screen: sudo ./update.sh -bg none
sudo ./update.sh -bg ~/Pictures/wallpaper.jpg
sudo ./update.sh -bg none
After uninstalling, GRUB has no Windows entry by design

GRUB's own Windows entry ("chainload") would ask for the recovery key every time, so grub-icon-menu keeps it switched off, also after uninstalling. Start Windows with Esc F9.

If you only want the normal text menu, do not uninstall: sudo ./update.sh --plain keeps the entry Windows Boot Manager (started by the UEFI firmware), which does not ask for the key. sudo ./update.sh --icons brings the icons back.

Ubuntu updates (kernel, GRUB, shim) nothing to do

Kernel updates run update-grub, which rebuilds the menu and picks the newest signed kernel for the Windows icon. GRUB and shim updates do not matter for BitLocker any more, because they are not part of Windows' start-up.

After a big Ubuntu upgrade (e.g. to the next release) run:

sudo ./doctor.sh
sudo ./update.sh
The clock is wrong after using Windows 5:30 h off
Why

Windows keeps the hardware clock in local time (IST), Ubuntu in UTC. After Windows, Ubuntu starts 5 hours 30 minutes ahead until it syncs over the internet. This laptop's boot log shows exactly that.

What to do

Tell Windows to use UTC too: administrator Command Prompt, then restart Windows:

reg add "HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /d 1 /t REG_DWORD /f

This only changes how the time is stored; BitLocker does not care.

Repair from a live USB Ubuntu does not start

Start the Ubuntu USB (Esc F9 → USB), choose "Try Ubuntu", open a terminal. On this laptop Ubuntu's root is encrypted (LUKS on nvme0n1p5, LVM inside), /boot is nvme0n1p4 and the EFI partition is nvme0n1p1. Check the names with lsblk -f first.

sudo cryptsetup open /dev/nvme0n1p5 dm_crypt-0    # asks for your disk password
sudo vgchange -ay
sudo mount /dev/ubuntu-vg/ubuntu-lv /mnt
sudo mount /dev/nvme0n1p4 /mnt/boot
sudo mount /dev/nvme0n1p1 /mnt/boot/efi
for d in dev proc sys run; do sudo mount --bind /$d /mnt/$d; done
sudo chroot /mnt rm -f /etc/grub.d/99_grub_icon_menu /etc/default/grub.d/99-grub-icon-menu.cfg
sudo chroot /mnt update-grub

This removes the icon menu; the normal Ubuntu menu comes back. Start Windows with F9.

4. Never do these

Can lock Windows or break booting
  • Start Windows from a GRUB entry that "chainloads" it, or turn os-prober back on (GRUB_DISABLE_OS_PROBER=false).
  • Clear the TPM, or switch Secure Boot off/on, without suspending BitLocker first.
  • Delete or reformat the EFI partition (nvme0n1p1), or delete firmware boot entries with efibootmgr -b … -B.
  • Install a BIOS update from Ubuntu without the recovery key at hand.
  • Start Windows from another system's boot menu (Kali, Mint, ...): it chainloads Windows too.
Always safe
  • Esc F9 at power-on, then Ubuntu or Windows Boot Manager.
  • sudo ./doctor.sh and sudo ./inspect.sh: they only read.
  • sudo efibootmgr --delete-bootnext: cancels a pending one-time Windows start.
